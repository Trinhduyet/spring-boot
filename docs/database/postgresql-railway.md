# PostgreSQL on Railway

The `postgres` Spring profile selects the PostgreSQL JDBC driver, a UTC database session and `classpath:db/migration-postgresql` for Flyway. The default SQL Server profile and its already-applied migrations are separate. Activate `dev,postgres` for Railway: `dev` configures the example HTTP Basic account, while `postgres` selects the database. The `local` profile permits all requests and must remain isolated from public networks.

Set variables on the API service in the **same Railway project and environment** as Postgres; `.railway.internal` DNS is isolated to that network. With a Postgres service named `Postgres`, Railway reference variables avoid copying passwords into the repository:

```text
SPRING_PROFILES_ACTIVE=dev,postgres
DB_URL=jdbc:postgresql://${{Postgres.PGHOST}}:${{Postgres.PGPORT}}/${{Postgres.PGDATABASE}}
DB_USERNAME=${{Postgres.PGUSER}}
DB_PASSWORD=${{Postgres.PGPASSWORD}}
APP_USERNAME=<API username>
APP_PASSWORD=<separate strong API password>
DB_FLYWAY_ENABLED=false
```

The `postgresql://` URL used by other clients is not a JDBC URL: Java needs the `jdbc:postgresql://` prefix. Keep application and database passwords separate and set secret values in Railway Variables, never Git. Railway TLS terminates at the public endpoint. Swagger UI and `/v3/api-docs` are public; `/api/**` requires HTTP Basic. Use **Authorize** in Swagger to supply the API credentials.

Before migrations, inspect PostgreSQL schemas, existing tables, Flyway history and data. Review [V1/V2](../../src/main/resources/db/migration-postgresql/) for that database. Flyway defaults to disabled; enable `DB_FLYWAY_ENABLED=true` for an approved fresh database initialization and then disable it again unless the operator has explicitly adopted automatic migration. Never use Hibernate `create`/`update` on an existing database, baseline a nonempty database blindly, or edit already-applied migrations.

The PostgreSQL schema uses `BIGINT GENERATED BY DEFAULT AS IDENTITY`, `BOOLEAN`, `NUMERIC(14,2)` and `TIMESTAMP(6) WITHOUT TIME ZONE` with a UTC convention. Case-insensitive uniqueness for SKU and category names/slugs uses `LOWER(...)` indexes. SQL Server and PostgreSQL collation and locking can still differ. SQL Server data is not automatically copied.

H2 remains the default test database. A local disposable PostgreSQL check or Railway startup can verify a particular version/schema; neither alone proves production locking, recovery, access control, or migration behavior for existing data. See [ADR 0006](../adr/0006-postgresql-and-swagger.md).
